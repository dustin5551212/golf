# Golf — Python

Six-card Golf, nine holes. Two to four players at a table, each on their own device.

**Play:** <http://domination-grind.tun.ply.gg:53177> — served from a desktop, so it is up
only while that machine is.

This is a Python port of a JavaScript implementation I wrote first. The JS original is not
published, but `tests/fixtures/parity.json` is generated by **running** it and is committed
here, so the port is checked against the original's actual output rather than a description
of it.

The rules and the server are Python. The **browser client is not ported** — it is the
same `public/` page, unchanged, and it talks to this server over the same HTTP/SSE
contract. A port that quietly re-implemented the UI would have doubled the surface
without adding a spec, so the client is a copy, and `tests/test_public_copy.py` fails
if it drifts from the original.

## Run

```sh
python -m golf.server            # → http://localhost:5174, 2-4 seats
python -m golf.server 5175       # another port
python -m golf --seed 42 --seats 3        # headless match, printed
python -m golf --seed 42 --seats 3 --trace  # every action, in order
```

Run those from the repository root — `python -m golf` finds the package through the
current directory. `pip install -e .` also puts a `golf` command on `PATH`:

```sh
golf --seed 42 --seats 3      # headless match
```

No runtime dependencies: standard library only (`http.server`, `threading`, `json`).
Development needs `pytest`:

```sh
python -m venv .venv
.venv/bin/pip install pytest
.venv/bin/python -m pytest          # 53 tests
```

One test skips when the JavaScript repo is not checked out beside this one — that is the
client-drift check, which has nothing to compare against on its own.

## How the port was proved, not just written

```
golf/engine.py      the rules             ← golf/src/engine.mjs   (314 lines, not published)
golf/view.py        the redaction boundary ← golf/src/view.mjs     (82 lines)
golf/server.py      HTTP + SSE transport   ← golf/src/server.mjs   (481 lines)
golf/policy.py      the deterministic bot used by tests and the CLI
golf/snapshot.py    canonical state dump, shared with the JS generator
tools/dump_parity.mjs   imports the JS source, writes the fixture
tests/fixtures/parity.json   1.4 MB of answers from the JS implementation
```

`tests/fixtures/parity.json` is **generated by running the JavaScript code**, never by
reading it. Regenerate after any rule change:

```sh
node tools/dump_parity.mjs                 # needs the JS source; GOLF_SRC sets its path
```

What it pins down, case by case: every card value and label, a 13 × 13 rank-pair
scoring grid, the mulberry32 stream for eight seeds, three full shuffled deck orders,
fifteen dealt positions, 302 scripted actions with the complete state after each,
fifteen refusal messages, six redacted views per seat, and four whole nine-hole
matches (292–548 actions each) with hole-by-hole scores and the terminal state.
Regenerated when knocking was added: 46 of those scripted steps now carry `knock` in a
seat's `legal` list, so the new action is parity-checked rather than assumed.

Layer by layer:

| Check | Command | Result |
|---|---|---|
| Rules, in Python idiom | `.venv/bin/python -m pytest tests/test_engine.py` | 18 tests |
| Redaction boundary | `... tests/test_view.py` | 8 tests, including a leak sweep over every seat at every step of a full match |
| Parity with the JS source | `... tests/test_parity.py` | every fixture case, byte-equal snapshots |
| Joined system | `... tests/test_system.py` | 52 cards conserved at every step, totals reconcile, same seed → identical run |
| Transport | `... tests/test_server.py` | rooms, refusals, polling, and a real SSE stream |
| Browser, two clients | Ada in Chromium, Bert over HTTP | `conn: live`; his swap reached her log in ~1.2 s over SSE |

## Things worth knowing before editing the rules

- **`discard` is a pass.** Discarding the drawn card moves the turn on and reveals
  nothing. That is a house rule, not the published one, and the port keeps it.
- **Two cards start face up**, slots 0 and 3 — the outer corners of the grid.
- **A card taken from the discard pile must be placed**; only a stock draw may be
  thrown away.
- **When a grid fills, everyone else gets exactly one more turn**, then the hole scores.
- **Knocking ends a hole from anywhere at the table.** Once every grid shows three
  face-up cards (`KNOCK_MIN_UP`), `legal` offers `{"type": "knock"}` to *every* seat, not
  just the player to move, and `apply` honours it out of turn — the one action that
  deliberately bypasses the turn check. It is refused mid-swap ("finish the turn in
  progress") so a held card can never be lost, and it ends the hole by flipping every
  card up and scoring (`_score_hole`), with no penalty. The engine records why a hole
  ended (`ended_by` → `endedBy` on the wire): `"knock"` or `"grid"`. The client uses it to
  hold a knocked hole on screen for four seconds (`KNOCK_REVEAL_MS`) before the totals,
  while a hole that filled up still goes straight to the scorecard.
- **The stock's contents never leave the server.** `golf/view.py` is the only place
  that decides what a seat is sent; build views from scratch there rather than
  deleting fields off an engine state.
- **Oddities are deliberate.** Error message text, log wording, the order of the
  stock, and the `Math.imul`-exact RNG are all copied from the source, because the
  parity fixture compares them. Do not "fix" them without regenerating the fixture.

Naming: the Python engine keeps the source's `apply` (not a keyword here) and uses
snake_case internally; the wire format in `view.py` stays camelCase because the
browser client reads `turnsLeft`, `discardTop`, `holeScore` and friends.

## Not covered yet

- **No benchmark.** The JavaScript version had none either, so this port matches it
  and is equally unmeasured. A `python -m golf --seed N --bench` throughput number
  would be the honest next step if the bot ever matters.
- **The SSE implementation is per-connection threads** (`ThreadingHTTPServer`), which
  is fine for a table of four and would not be for hundreds. The JavaScript version
  used a single event loop; this one trades that for a plain-stdlib transport.
- **`public/` is a copy.** Fixing a UI bug means editing the page here and in the
  JavaScript original; the drift test enforces that when both are present, and skips
  when only this repo is checked out.
